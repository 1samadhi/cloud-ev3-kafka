## Que se probo

Se publicaron a mano dos mensajes defectuosos en `pagos-resultado`:

1. `{esto no es json valido` — JSON sintacticamente roto.
2. `{"idOrden":null,"estado":"INVENTADO","monto":-5}` — JSON valido, invalido para el dominio.

## Resultado

`pagos-resultado.DLT` paso de 0 a 2 mensajes. El manejador distinguio las dos causas:

```
JSON roto       causa=JsonParseException       -> DLT inmediato
campo invalido  Fallo 1 procesando... (reintento)
                causa=InvalidFormatException   -> DLT tras el reintento
```

El reintento intermedio confirma la politica del `DefaultErrorHandler`: reintentar
lo que puede ser transitorio y descartar de inmediato lo que reintentar no arregla.
