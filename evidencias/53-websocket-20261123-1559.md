# Evidencia: metricas en vivo por WebSocket (+3)

Fecha: 2026-11-23 15:59 (-03)   ·   AWS, 44.208.92.186

## Endpoint

`ws://44.208.92.186:8084/ws/metricas` en ms-recomendaciones. El servidor empuja un
snapshot cada 2 s a cada sesion conectada; el cliente no pide nada.

No pasa por el API Gateway REST a proposito: una API REST de API Gateway no
habla WebSocket (eso requiere una API de tipo WebSocket, que es otro recurso).

## Validacion de origen

El handshake comprueba el `Origin`, con la misma lista que CORS:

```
Origin: http://44.208.92.186:8090        -> HTTP/1.1 101  (Upgrade: websocket)
Origin: http://otro-origen.test -> HTTP/1.1 403  (rechazado)
```

Esto impide que una pagina ajena abierta en el navegador de un operador lea
las metricas de la tienda.

## Snapshots recibidos

Tres interacciones enviadas antes de conectar, y luego:

```
mensaje 1: tipo=METRICAS interaccionesPorMinuto=2 usuariosActivos=1 topProductos=2
mensaje 2: tipo=METRICAS interaccionesPorMinuto=3 usuariosActivos=1 topProductos=3
mensaje 3: tipo=METRICAS interaccionesPorMinuto=3 usuariosActivos=1 topProductos=3
```

Los valores cambian entre snapshots (2 -> 3), que es lo que prueba que son
metricas vivas y no un valor fijo.

## Nota sobre la configuracion

`docker-compose.yml` fija `CORS_ORIGENES` a localhost, asi que en AWS el
handshake rechazaba al propio front (403 incluso desde el origen correcto).
Se corrige con `docker-compose.override.yml`, sin tocar el compose original.
